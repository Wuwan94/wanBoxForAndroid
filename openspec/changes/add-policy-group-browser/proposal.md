# 提案：策略组浏览、选择与测速（批次 2）

## 背景

wanBox 的生成配置里始终存在原生策略组：主组（tag `proxy`，selector / urltest /
loadbalance 三选一）、各负载均衡实体的 urltest / loadbalance 组，以及路由引用的
组名出站。但管理端没有一个能按「运行中配置的真实面貌」浏览这些原生组的界面：
用户只能在配置列表里改数据库模型，无法看到某个组当前实际选中了哪个成员，
也不能对某个具体的组做运行时切换或整组测速。参考项目 NetProxy-Magisk 的
「代理页浏览原生 Selector/URLTest 组、选节点、测速」正是这一块能力；
wanBox 只借鉴该功能形态，不照搬其代码与配置模型。

## 目标

- 新增「策略组」页面，数据来自运行中核心的控制器（Clash API）快照：
  列出全部原生组（类型、当前选中、成员数），展开看成员。
- 对 Selector 组可运行时切换成员，切换后回读校验，以服务器真值为准。
- 对任意组可整组测速：逐个成员测延迟，失败显式标注，不伪造数值。
- 核心未运行或控制器不可达时显示明确空状态，绝不拿数据库显示名猜测
  或拼凑组数据（与仓库既有原则一致，见 RunningProfileTagResolver）。

## 非目标

- 不做组的图形化编辑（成员增删、类型与测速参数修改）——批次 4。
- 不改 ConfigBuilder 的配置生成、不改路由生成顺序、不改组 tag 规则。
- 不新增模块侧命令；只用既有控制器接口与 `node tags` 运行快照。
