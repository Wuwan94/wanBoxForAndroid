# 提案：UI 按模块功能对齐（批次 3）

## 背景与盘点结论

按「APK 界面以 Root 模块实际功能面为事实源」逐项盘点（对照表见 design.md）：
模块的启停/状态、节点选择与故障转移、智能自动停、健康检查、热更新、遥测、
混合入站、规则资产、路由模式等能力均已有对应界面；全部设置项均有消费方，
全部 Activity/Fragment 均可达，未发现可证明无后端支撑的入口。

唯一确证的缺口在模块诊断：监督器把每次核心退出的原因持久化在状态里
（lastExit / lastReason / lastExitAt + events），模块注释明言是「让管理器
能向用户解释掉线」；管理器也已把 health、lastExit、lastReason、retryCount、
events 全部解析进 Status，但除首页失败时引用一句 lastReason 外，
retryCount、events、lastExit 与退出时间从未在任何界面呈现。核心反复
崩溃时，用户看不到第几次重试、退出码与事件经过。

## 目标

- 设置页「Root」区的模块状态从一行扩为诊断块：呈现模块已上报的健康状态、
  最近一次退出（退出码、原因、时间）、看门狗重试次数与最近事件（有界）。
- 字段缺失（旧模块不上报）时整项隐藏，绝不显示编造或占位假值。
- 盘点对照表随本变更落盘，作为本批「无可删入口」的证据记录。

## 非目标

- 不删任何入口（盘点未证明有死入口；删除须另有证据，另行立项）。
- 不改模块协议与 Go 代码：只消费状态里已有字段；lastExitAt 若解析缺失
  只在 App 侧补可选解析。
- 不改 cgroup 内存治理（模块不上报其状态，界面无从呈现，记录在对照表）。
