## 基线与边界

- 2026-11-10 核对远端 `main`：`70fbaac73876d25550df51e9bdd673396169ec66`；当前已发布预览为 `v3.0.13-preview.2`，正式版 `v3.0.11`。

- 保持包名、签名配置、备份格式、数据库 schema、Root 模块与管理器版本配套规则不变。最新预览保留规则维持原样，只有以后另行授权发布并完整核验新资产后才可清理旧预览。

## 修改与原因

### 更新网络路径

- 调用链核对发现，当前瘦管理器的 `WanHttpClient.tryProxyOutbound()` 实际为空操作，不能将方法名当作已走核心代理的证据。
- 更新元数据和所有资产统一使用 `UpdateTransport`，显式连接用户配置的本地 mixed 入站（端口及可选认证）。入站关闭、不可达或认证失败会失败，不回退直连；不改变订阅等其他 HTTP 调用点。
- 保留默认 TLS 证书及主机名验证，只接受 HTTPS，不允许 HTTPS 降级重定向；保留超时、SHA-256 完整性及显式安装/模块导出入口。协程取消会关闭底层请求和流读取。
- 行为边界：核心 mixed 入站不可用时无法在线检查或下载更新；这是明确失败，不会绕过用户策略直连。实际节点/Root 核心联网仍需真机验证。

### 页面生命周期

- 读取许可证、检查更新、下载和导出不再通过 `Asyncs.kt` 的 `GlobalScope` 辅助函数启动，改由 view lifecycle scope 持有；离开页面 `onStop` 取消更新任务并关闭对话框，销毁视图进一步释放 UI。
- 同一页面只允许一个在途更新操作；取消保留取消语义，迟到结果不再触碰旧 UI，异步结果不使用失效的 `requireContext()`。
- 没有对所有 `Asyncs.kt` 调用点做跨项目重构，避免改变与本次更新链路无关的任务生命周期。

### Tag 发布门槛

- 正式版和预览版使用共享检查脚本。只有 `gh api` 明确返回 HTTP 404 才认定不存在；已存在、403/429/5xx、网络错误均拒绝继续。
- 已只读核对真实不存在 Tag 的 GitHub API 错误格式；测试覆盖存在、404、权限/限流/网络等其他错误。

### 最终 Manifest 安全检查

- 检查目标改为构建生成的 `packaged_manifests/<variant>`，缺失即失败，不能退回只检查源文件。
- 精确白名单同时核对组件类型、全名、权限和 action 集；涵盖 launcher、必要系统服务及依赖组件，额外导出组件或权限漂移会失败。
- CI 对 Debug 和实际 Release 变体的最终 Manifest 执行检查；保留原有私有控制入口、TLS 和备份安全检查。

### Geo 构建输入

- 构建不再读取 `latest`；`buildScript/lib/geo-assets.lock.json` 固定发行版本、精确 URL 和 SHA-256。两项均下载并验证成功才写入打包输入，错误不使用未校验回退。
- GeoIP：`20261012`，SHA-256 `f24050f4ce11783cd632fe3982f24895d959fa01afc8fab6ca8a6a3615b5de56`。
- GeoSite：`20261108011013`，SHA-256 `2b763c631fe974e296b2420d30a185a98152de662f6280997fa856dd95bd7280`。
- 生成 `geo-provenance.json`，将来源、版本和摘要写入构建日志及 GitHub Step Summary；资源升级必须显式修改 lock 并审查，不由时间隐式决定。

## 唯一新增功能候选：URLTest 故障回退策略

- 官方来源：sing-box URLTest 文档，<https://sing-box.sagernet.org/configuration/outbound/urltest/>；同时核对项目锁定的 reF1nd/sing-box 源码提交 `17397d022647b73378705e1f91ff031dddaaec21`，不将上游最新能力直接等同于当前 pin。
- 用户价值：可评估 `fallback.enabled` / `max_delay`，优先使用配置顺序中可用且延迟满足要求的节点，而非总追逐最低延迟；适合希望主节点稳定、故障才切换的分组。
- 兼容性与风险：当前管理器配置模型没有这组字段，需额外序列化、配置转换和 pinned core 行为测试；还可能改变现有 URLTest 选择语义。不得破坏现有连接保护、idle timeout 下限及 `interrupt_exist_connections=false`。
- 结论：只列候选，不在稳定性 PR 实现，不扩大本轮修复范围。

## 瘦管理器补充（2026-11-10）

- 用户选择瘦管理器后，统一普通构建、PR 验证和发布的配置：`wanboxThin` 默认开启，显式 `-PwanboxThin=false` 仅用于诊断嵌入核心。预览/正式发布脚本原本已传 `-PwanboxThin=true`，本轮解决的是 PR CI 和日常构建默认仍带 JNI 的不一致，不声称新发明了已有瘦模式。
- PR CI 对实际签名比较 APK 强制执行无 native payload 校验及保留功能/规则资源检查；下载体积门禁同时检查模块 ZIP + APK 的 26,214,400 字节（25 MiB）绝对预算，不能只用相对回归通过掩盖超标。
- 新增已安装 APK 的 Android 仪器化测试：确认 `WITH_CORE=false`、不含 `.so`，Kotlin HTTP 客户端不加载 JNI，离线 Geo 数据库可由 Kotlin 解压落地。编译、模拟器执行和 Root 真机验证分别记录；测试源码存在不代表已执行通过。
- 沿用现有瘦模式边界：模块负责代理核心；订阅/更新走 Kotlin HTTP，TCP 重测保留。依赖进程内 JNI 的 URL/带宽测速和 STUN 已由原有门控隐藏或明确拒绝，本次没有新增删功能，也不把这些功能称作已迁移至模块。Root 未安装/版本不匹配仍须明确提示。
- 不改包名、签名、版本号、备份和数据库格式；只更新此 PR，不合并、发布或删除 Release/Tag。正式签名产物及实际聚合体积以本提交的新 CI 制品为准，旧 37.39 MiB 不能当作瘦构建实测值。
